変更前の手順

ファイルのパスから、確認する場所へ。

何を直し、どのテストを実行するかは開発者が決めます。その判断に必要な最初の手掛かりを、グラフから得られます。

01

comP が地図を作る

ファイル、シンボル、依存関係をローカルの SQLite に索引します。コードを探すときは comP 自体の検索や影響グラフも使えます。

02

MAGATAMA が波及先をたどる

変更予定のファイルを渡すと、索引済みの呼び出し元や利用箇所を追います。comP が複数ルートを索引していれば、ルートをまたぐ関係も対象です。

03

根拠を見て確認する

候補ごとにファイル、距離、関係の種類、どのシンボルを経由したかを返します。そこから読むコードとテストを選べます。

コードの関係だけではない

以前の判断も、ファイルから探せる。

comP の作業履歴があれば、MAGATAMA は過去の依頼を、その中で話題になったファイルやシンボルへ結び付けます。変更前に、そのコードについて以前何が話されたかを調べられます。

comP 自体にも session_recall があります。MAGATAMA はコードを入口として履歴を見る手段を加えます。comP の会話記録はベータ機能で既定では OFF です。履歴表示には、プロジェクトの .comp に記録が必要です。

先に確かめたい二つのこと

「ここを直したら、どこを確認する？」
「以前、なぜここを変更した？」

変更範囲の解析とエンティティの履歴

現在のソースで試す

自分のコードで、波及候補を見る。

ファイル単位の変更範囲解析は MAGATAMA v0.7.0 に含まれます。以下はソースのチェックアウトから試す手順です。

  1. comP を起動。 VS Code 拡張を導入し、対象プロジェクトに .comp/index.db ができたことを確認します。
  2. MAGATAMA をソースから実行。 下のコマンドで環境を用意し、MCP クライアントに magatama serve を登録します。
  3. 実際のファイルを指定。 プロンプトのパスを、索引のあるプロジェクトと変更予定のファイルへ置き換えます。

ソースの準備

git clone https://github.com/tsucky230/MAGATAMA.git
cd MAGATAMA
uv sync --all-packages --dev
uv run magatama info

波及候補と依存関係の根拠を教えて。

メインルートは相対パス、追加ルートは対応する comP の版で絶対パスを使います。同名のファイルにはフルパスを指定してください。パスが曖昧な場合、索引に依存関係がない・読み飛ばした関係がある場合、またはファイルが二重登録されている場合は risk=unknown として確認を促します。

数字の読み方

一つの概要把握の計測。万能な節約率ではありません。

この数字は、以前このリポジトリで行った概要把握の実験です。当時の一つの作業で二つの入力を比較したもので、変更影響の正確さや、別のプロジェクトでも同じ節約率になることは示しません。

変更確認では、返ってきたパスと関係をコードやテストと照合してください。MAGATAMA の high / medium / low は索引上の関係に基づく目安です。
