The workflow

Go from a file path to a review plan.

You still decide what to change and test. The graph makes the first pass faster to inspect.

01

comP builds the map

It indexes files, symbols, and dependencies in a local SQLite database. Its own search and impact tools are useful when you need to locate code.

02

MAGATAMA traces the change

Give it the files you plan to edit. It follows indexed dependencies to callers and users, including other roots when comP has indexed them.

03

You inspect the evidence

Each affected symbol includes its file, distance, relationship, and the symbol through which it was reached. Use that list to choose code and tests to inspect.

More than a call graph

Recover the reason behind the code.

When comP history exists, MAGATAMA links past requests to the files and symbols they discussed. Ask about a file before changing it and see both the past conversation and the current indexed impact.

comP already offers session recall. MAGATAMA adds a code-centered route into that history. Conversation recording in comP is a beta feature and is off by default; the history view needs records in the project's .comp directory.

Try the current source

See a result on your own code.

The new file-scoped tool is in this change. Use a checkout containing it. A fresh clone of the default branch will have it after this change lands there; the published PyPI package does not have it yet.

  1. Start comP. Install the VS Code extension, open your project, and confirm that .comp/index.db exists.
  2. Run MAGATAMA from source. Clone the repository, then run the commands below. Register the resulting magatama serve command in your MCP client.
  3. Ask about a real file. Replace the placeholders in the prompt with paths from your indexed project.

Show each affected file and its dependency reason.

The main root uses relative paths. Additional roots use absolute paths in comP builds that support them. Use full paths for same-named files. An ambiguous path, an index without dependency edges or with skipped edges, or duplicate file entries produce risk=unknown.

These numbers come from an earlier experiment on this repository. They compare two inputs for one overview task on an older snapshot. They do not measure impact accuracy or promise the same saving on another project.

For a change review, inspect the returned paths and edges against source and tests. MAGATAMA's high/medium/low risk label is a heuristic over the index.
