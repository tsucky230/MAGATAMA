# comP × MAGATAMA 連携仕様と調査結果

この文書は、comP の現行ソースと MAGATAMA の実装を突き合わせ、変更範囲の解析・履歴連携の契約、確認済みの制約、次に試す応用を記録するものです。`analyze_change_scope` は MAGATAMA v0.7.0 に含まれます。

## 調査した範囲

| comP の変更・データ | MAGATAMA への影響 | 今回の対応 |
| --- | --- | --- |
| `.comp/index.db` の `files` / `nodes` / `edges`、追加ルートの絶対パス | 同名のファイル・シンボルが複数ルートに存在する | ファイル指定を優先し、曖昧な照合を拒否。ルートをまたぐ依存関係を解析 |
| Windows パスの複数表記 | 同一ファイルが別の索引項目に見えることがある | 表記を正規化して二重登録を検出。検出時は `risk_level=unknown` |
| `.comp/session-memory.json` / `.comp/history/*.jsonl` と記録の trace 欄 | 履歴を間違ったコードへ結び付けると判断を誤る | 一意なファイル・シンボルにだけ `DISCUSSED` を作り、限定した trace 欄を履歴に残す |
| comP の `get_impact_graph` と `session_recall` | MAGATAMA の価値を重複機能として説明しやすい | ファイル単位の変更確認と、コードを入口とする履歴照会を追加価値として説明 |
| 会話自動記録のベータ状態 | 記録がない環境で履歴機能を過大評価しやすい | README と Pages で既定 OFF、既存履歴が必要と明記 |

確認対象は MAGATAMA と comP のローカル作業ツリーです。comP の追加ルート対応には未コミット変更が含まれます。comP の別版との互換性を保証する表ではありません。

## `analyze_change_scope` の契約

両方の MCP サーバー実装に、同じ名前の読み取り専用ツールを追加しました。

```text
analyze_change_scope(path: str, files: list[str], depth: int = 3)
```

`path` は対象プロジェクト、`.comp` ディレクトリ、または `index.db`。`files` は索引中のファイルパスです。メインルートは通常相対パス、追加ルートは対応する comP の版で絶対パスです。`depth` は 1〜10 に収めます。ツールは毎回索引を読み直し、対象ファイル内の全シンボルから、依存関係を逆方向にたどります。包含関係と履歴の `DISCUSSED` はコード依存として数えません。

成功時は `changed_files`、`changed_symbols`、`affected_symbols`、`affected_files`、`impact_score`、`risk_level`、`depth_analyzed` に加え、`db_path`、comP metadata、読み込めなかった edge 数を返します。各 `affected_symbols` にはファイル、距離、関係の種類、経由したシンボル ID を含めます。`impact_score` と high / medium / low は索引上の近さと件数に基づく目安です。

存在しないパスや複数の候補に一致するパスは `success=false`、`risk_level=unknown` で返します。索引にシンボルや依存 edge がない、edge を読み飛ばした、同一ファイルのパス表記が二重登録されている場合もリスクは unknown です。索引に載らない動的呼び出しや実行時の挙動は、この結果からは判断できません。

## 履歴照会の契約

`read_external_sessions(path, mode)` は履歴を `SESSION` エンティティとして読み込み、対象が一意に決まるファイル・シンボルに `DISCUSSED` を作ります。`ambiguous_files` と `ambiguous_symbols` は結び付けを見送った件数です。trace から読み込むのは agent、session / turn ID、親 turn ID、kind、commit、test の終了コード、rules の file / heading / hash に限ります。任意の JSON 欄は履歴結果へ複製しません。

`get_entity_history(name, path, limit, analyze)` は同名の候補が複数ある場合、候補パスを示して失敗します。明示された `path` の索引・履歴読み込みに失敗した場合、前に読み込んだグラフの結果をそのプロジェクトの結果として返しません。履歴の記録と解析結果は、現在のコードの正しさを証明するものではありません。

## 修正した不具合と確認事項

- Claude Stop hook の transcript 解析を `message.content` の実データ構造に合わせました。最後の未回答 turn を読み、一般的な秘密情報の形を出力前に伏せます。
- 引継ぎ生成では、対象が親リポジトリの中にあるだけの場合に、親の Git 状態を対象の状態として表示しないようにしました。
- MAGATAMA の実索引には、メインルートの相対パスと `//?/E:/...` の絶対パスが同じファイルを指す項目が4組ありました。修正済み comP daemon で全件索引を一周させ、ファイル数は227から223、二重登録は4組から0組になりました。SQLite の整合性検査は `ok`、外部キー違反は0件です。修復後の MAGATAMA 読み込みは4,381エンティティ・8,810関係・読み飛ばし0件で、当該ファイルの変更範囲解析は `risk_level=high` を返しました。この波及件数は効果の測定値として扱いません。
- 2026-11-17の再確認で、稼働していた旧 release daemon から `//?/` 形式の行が6件再発していました。旧 daemon 5プロセスを停止し、上記の修正を含む現行 comP ソースで release 版をビルドしました。さらに MAGATAMA の `.mcp.json` が VS Code 拡張同梱の旧バイナリを指していたため、ローカルの新しい release 版へ切り替えました。全件索引を実行した結果、ファイル数は223、`//?/` 形式の行は0件になりました。SQLite の整合性は `ok`、外部キー違反は0件で、MAGATAMA の変更範囲解析は読み飛ばし0件・`risk_level=high` です。

## 次に広げられる使い方

| 優先 | 案 | 開発者にとっての利点 | 実現前の確認 |
| --- | --- | --- | --- |
| 1 | PR 差分のファイルをまとめて解析し、差分外の呼び出し元をレビュー候補にする | 見落としやすい利用側を早く確認できる | Git 差分と索引の時点が一致すること、誤検出率 |
| 2 | 変更範囲から関連テストを**候補として**提示する | テストを選ぶ手間を減らす | テストと対象コードの対応根拠、実測の再現率 |
| 3 | 複数ルートの境界をまたぐ変更を、利用プロジェクト別に表示する | 共有ライブラリ更新時の連絡先を探しやすい | comP の追加ルート形式が安定し、重複パスが解消すること |
| 4 | 履歴の trace とコードの edge を一緒に表示する | 影響箇所と過去の判断を同じ確認画面で追える | 履歴の機密情報・保存期間・記録の欠落への扱い |

これらは構想です。自動テスト選択、PR コメントの自動投稿、複数ルート別の画面は現行機能ではありません。まずは実プロジェクトで「変更前に見つかった差分外の確認箇所」と「誤検出」を記録し、次の設計判断に使います。
